## 2024-06-14 - [Markdown Viewer Reverse Tabnabbing and XSS Protection]
**Vulnerability:** Reverse tabnabbing vulnerability via user-supplied markdown. When external links are clicked, they might open in a new tab but still retain a reference to the `window.opener`. This allows the newly opened tab to manipulate the original page (e.g. redirecting to a phishing site). In addition, we need to ensure XSS vectors using `javascript:` inside anchor tags are not inadvertently bypassed when rewriting markdown.
**Learning:** `marked` renderer does not automatically add `target="_blank"` or `rel="noopener noreferrer"` to external links. Also, trying to fix this by using `DOMPurify` hooks can cause unintended side effects (race conditions affecting all instances). The proper fix is using a customized `marked` renderer specifically scoped to this component that carefully targets only external HTTP/HTTPS links without breaking anchor hashes.
**Prevention:** Always use `rel="noopener noreferrer"` in conjunction with `target="_blank"` for external links. Prefer component-scoped markdown renderers instead of registering global DOMPurify hooks. Validate that `href` explicitly uses external protocols (e.g., `http://`, `https://`, `//`) via a case-insensitive check before modifying the HTML.
