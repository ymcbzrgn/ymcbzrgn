## 2025-02-14 - DOMPurify Hook Memory Leak & Secure Link Handling
**Vulnerability:** External links rendered via Markdown to HTML (and then sanitized) were lacking robust protections against reverse tabnabbing (`target="_blank"` without `rel="noopener noreferrer"`), and dynamically attaching DOMPurify hooks (e.g. `afterSanitizeAttributes`) inside React components could lead to memory leaks or unintended global sanitization side-effects since the hooks persist globally.
**Learning:** `DOMPurify.addHook` adds hooks globally. When used inside a component's render or useMemo cycle, it can accumulate hooks or affect sanitization elsewhere in the app. Also, blindly applying link protections to all links can break internal navigation; we need to scope them strictly to external URLs (e.g. `http://` or `https://`).
**Prevention:** Always immediately call `DOMPurify.removeHook` after the `DOMPurify.sanitize` call when defining hooks dynamically in a localized scope. Furthermore, restrict adding `target="_blank"` and `rel="noopener noreferrer"` solely to external links.
