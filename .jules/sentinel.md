## 2025-02-14 - Target Blank External Link & XSS Vulnerability in Markdown Rendering
**Vulnerability:** External links parsed by the Markdown viewer (`marked`) were lacking `target="_blank"` and `rel="noopener noreferrer"`. Also, links using `javascript:` schemes could bypass DOMPurify constraints if rendered improperly or configured loosely, exposing a potential Cross-Site Scripting (XSS) vulnerability.
**Learning:** `DOMPurify` is excellent, but we must protect against external links targeting the same window which poses security and usability risks. When intercepting and overriding Markdown rendering rules for older vs. newer library versions (like `marked` v11+), custom renderer methods must accommodate single `token` object arguments instead of individual parameters.
**Prevention:** Implement a custom `marked.Renderer` to dynamically append `target="_blank"` and `rel="noopener noreferrer"` for standard external links (starting with `http://`, `https://`, or `//`), and block entirely `javascript:` links. Always perform case-insensitive checks and test against both `string` and `object` token parsing structures to ensure compatibility and prevent XSS.
