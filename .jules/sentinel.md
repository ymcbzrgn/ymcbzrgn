## 2025-02-20 - [Avoid DOMPurify Hook Mutation in React Components]
**Vulnerability:** Adding and removing global `DOMPurify` hooks (e.g., `DOMPurify.addHook`) inside a React component's `render` or `useMemo` block introduces severe race conditions and permanently corrupts global state. If two components sanitize HTML simultaneously, one component's `finally` block will clear the hook while the other is still running, leaving HTML unprotected. Furthermore, calling `DOMPurify.removeHook` unconditionally clears **all** hooks registered globally for that lifecycle event.
**Learning:** `DOMPurify` is a global singleton. It must not be mutated dynamically within a React lifecycle. Applying security properties (like `target="_blank"` and `rel="noopener noreferrer"` for external links to prevent reverse tabnabbing) should be handled by the HTML parser/renderer *before* it reaches the sanitizer.
**Prevention:** Override the Markdown renderer (e.g., `marked.Renderer.link`) to safely inject the `target="_blank"` and `rel="noopener noreferrer"` attributes into the HTML string before DOMPurify executes, relying on DOMPurify's allowlist (`ALLOWED_ATTR: ['href', 'class', 'target', 'rel', 'title']`) to pass the attributes through safely.
